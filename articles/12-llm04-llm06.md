# Article 12: LLM04–LLM06: Supply Chain, Poisoning and Unbounded Consumption

Three LLM security risks can look very different, but they share a common theme:

> The AI system can be compromised through what it consumes, what it learns, or what it is allowed to consume.

## LLM04 — Supply Chain

The application may depend on:

- Models
- Packages
- Datasets
- Plugins
- Connectors
- Containers

A compromised component can introduce malicious behavior before the system even reaches production.

## LLM05 — Data and Model Poisoning

An attacker may manipulate data used for:

- Training
- Fine-tuning
- Evaluation
- Retrieval

The objective is to influence downstream model behavior.

The important control is provenance.

Can we answer:

- Where did this data come from?
- Who modified it?
- Which pipeline processed it?
- Which model version consumed it?

## LLM06 — Unbounded Consumption

AI systems can also be attacked through resource consumption.

Examples include:

- Extremely large inputs
- Excessive requests
- Recursive agent loops
- Repeated expensive inference
- Token exhaustion
- Resource-intensive workflows

This can become a security and availability problem — and potentially a financial problem.

## Common control pattern

**IDENTIFY → VALIDATE → LIMIT → MONITOR**

For supply chain: validate artifacts.

For poisoning: validate data lineage and integrity.

For consumption: limit resource usage.

Useful measurements include:

- Supply-chain integrity coverage
- Poisoned-data detection rate
- Resource exhaustion detection rate
- Token/request budget violations

The important point is that AI security is not only about malicious prompts.

> **The attack surface includes what the system trusts, learns from and consumes.**
